# Builder App and Self-Hosted Phone Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A release with a Mac and a Windows builder app that turns the player's own PS4 copy into a playable game whose phone page is hosted from the player's computer.

**Architecture:** The game serves its bundled phone page from the native library (iwyknet, Go) and publishes it through a bundled `cloudflared` quick tunnel, or uses a Worker address the builder deployed to the player's own Cloudflare account. The builder is a PySide6 wizard around the existing `pipeline` package, frozen with PyInstaller, built by GitHub Actions together with the prebuilt native pieces.

**Tech Stack:** Python 3.11+ (pipeline, builder, PySide6, PyInstaller), Go (iwyknet, pion), C# Unity 6000.6.10f1 (port runtime), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-27-builder-design.md`

## Global Constraints

- Nothing from the game or the app is committed or attached to a release. The APK is never shipped.
- APK accepted only with SHA-256 `6bf13282cd189e3a960e56fff0f8f5acd1e4460d831d0c21ee022c55889379d5` (1.6, build 1623); "Find it" opens `https://www.google.com/search?q=site%3Awww.apkmirror.com+thats+you+1.6+apk+download`.
- Game title must be CUSA08389; base and update each as a folder or a fake PKG.
- Every downloaded tool is pinned in `pipeline/versions.json` with URL and SHA-256 per platform.
- Each builder builds for its own OS only: macOS arm64, Windows x64.
- Own code lives in `unity/Port`, `web/`, `native/`, `pipeline/`, `tools/`, `builder/`, `.github/`.
- ASCII hyphens only, no AI attribution, commit identity 007hacky007, short imperative commit messages.
- The private page address never appears in tracked files (pre-push hook enforces it).

## Review Focus

1. Tunnel never comes up (offline, firewall, cloudflared crash): the QR overlay must say why and keep retrying, the game must stay playable from the menu.
2. Builder interrupted mid-build (closed, crash, power): next start resumes from the last finished step instead of redoing the hour-long import.
3. Paths with spaces and non-ASCII letters (Windows user folders, "That's You!" with an apostrophe): every subprocess call uses argv lists, never shell strings.
4. Not enough disk space or a wrong input (retail PKG, other title, APK of another version): refused before anything long starts, with a plain sentence.
5. Unity installed but not licensed: detected before the build step, with the sign-in instruction, not as a failed import an hour later.
