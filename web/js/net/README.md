# Phone page logic layer (unit U3)

Modules:

- `web/js/util/`: `emitter.js`, `clock.js` (real clock and a fake one with `advance`), `storage.js` (`iwyk.` prefix, in-memory fallback), `log.js` (ring buffer).
- `web/js/net/`: `params.js` (QR fragment), `sdp.js` (answer SDP of contract 2.5), `frames.js` (envelope of 2.1 and 2.2), `messages.js` (builders of 5.5, validators for game messages), `link.js` (one session: hello, pings, timeouts, chunked sends), `transport.js` (the only module that touches browser APIs), `content.js` (uploads, downloads, blob store), `resources.js` (manifest handshake).
- `web/js/game/`: `device.js`, `profile.js`, `state.js`, `machine.js` (views and commands of 5.6), `game.js` (`createGame` of 5.4).

UI units use only `createGame`. Tests: `node --test web/test/net web/test/game web/test/util`.

## Deviations from the contract and additions

None of these changes a shared wire format.

1. `params.js` is stricter than 5.4. `u` and `w` must use the ICE character set `[A-Za-z0-9+/]`, and `t` must be printable ASCII with no spaces. Values generated by U1 (`[A-Za-z0-9]`) always pass.
2. Each choice in the answer view has an extra `value` field. It holds the AnswerIndex that is sent when the choice is picked.
3. Timeouts while joining or during the handshake show the `nogame` popup only until this page load has received a `joined` frame. After that the page shows `failed` and reconnects.
4. `bye` with reason `shutdown` also sets `lastJoin.active` to false, so a reload does not auto-join a game that has quit.
5. Forced sends (`SendDrawing`, `SendQuickDrawDrawing`, `SendMimicThisPhoto`) wait up to 5 s for the draft provider. The view switches to holding look-at-tv only if no newer view has arrived in the meantime.
6. `profileEdit('name')` follows 5.6 exactly: it goes through card and selfie again rather than straight back to confirm.
7. `createGame` accepts optional extras for tests and integration: `device`, `uuid`, `random`, `makeUrl`/`revokeUrl`, `visibility`, `timing`/`linkTiming` and `draftTimeoutMs`. It also exposes `wake()`, `uid`, `destroy()` and `thumbnails.has/on`. By default, `browserEnvironment()` and `watchVisibility()` in `transport.js` supply the device values and the visibility hooks. That keeps all DOM access in one module.
8. Text frame cap: received text frames over 65536 UTF-8 bytes are dropped. The check counts UTF-8 bytes, not UTF-16 code units.
9. Reassembly (2.2, "more than 4 partial transfers"): the page never fails a transfer because of this rule. When a fifth transfer starts while 4 are still partial, the oldest partial is abandoned and logged. A sender sends each transfer back to back, so an open partial at that point is stale, and abandoning it stops a few stuck transfers from blocking content for the rest of the link.
10. Memory caps against a broken game:
    - The blob store keeps at most 120 entries. Entries the manifest marks Required are skipped by LRU eviction but still count. Once the store passes twice its capacity, the oldest entries are evicted even if they are required.
    - At most 64 download headers wait for their binary at once; the oldest is dropped first. Each header also expires after 60 s.
    - At most 8 binaries wait for their header at once. Each expires after 10 s.
